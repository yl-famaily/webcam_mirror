# Webcam Mirror

바탕화면 위에 작은 웹캠 창을 띄우는 Windows 오버레이 앱.
테두리 없는 창을 마우스로 자유롭게 옮기고, 크기·비율·모양을 바꿀 수 있다.

## 설치

Python 3.12 이상 (3.14 에서 개발·검증).

```bash
python -m pip install -r requirements.txt
```

`opencv-contrib-python` 을 쓰지만 `opencv-python` 으로 바꿔도 동작한다 (둘 다 설치하면 `cv2` 파일이 충돌하니 하나만 둘 것).

## 실행

```bash
python main.py
```

처음 실행하면 주 모니터 우하단에 320×240 크기의 타원 창이 뜬다.

## 조작

| 동작 | 방법 |
| --- | --- |
| 이동 | 창 안쪽을 좌클릭 드래그 |
| 크기 조절 | 창 가장자리(10px)를 드래그 — 8방향 |
| 비율 고정 | 메뉴 → 비율에서 고르면 어느 모서리를 끌어도 그 비율이 유지됨 |
| 자유 변형 | 비율을 `자유` 로 두면 가로세로가 따로 움직임 (기본값) |
| 현재 비율 유지 | 자유 모드에서 드래그 중 `Shift` (또는 메뉴 → 비율 → 현재 비율 유지) |
| 확대 / 축소 | 창 위에서 마우스 휠 |
| 모양 전환 | 창을 더블클릭 (원형 ↔ 사각형) |
| 설정 패널 | 창을 **가운데 버튼(휠) 클릭**, 또는 `Ctrl+Alt+S`, 또는 메뉴 → 설정 열기 |
| 전체 메뉴 | 창에서 우클릭, 또는 트레이 아이콘 우클릭 |
| 표시 / 숨기기 | 트레이 아이콘 클릭 |

## 전역 단축키

| 키 | 기능 |
| --- | --- |
| `Ctrl+Alt+M` | 창 표시 / 숨기기 |
| `Ctrl+Alt+F` | 좌우 반전 (거울 모드) |
| `Ctrl+Alt+T` | 항상 맨 위 토글 |
| `Ctrl+Alt+C` | 클릭 통과 토글 |
| `Ctrl+Alt+S` | 설정 패널 열기 / 닫기 |

다른 앱이 이미 쓰고 있는 조합이면 해당 단축키만 조용히 등록되지 않는다. 기능은 메뉴에서 그대로 쓸 수 있다.

## 메뉴 기능

- **모양** — 원형/타원, 사각형, 없음(전체)
- **비율** — 자유 / 1:1 정사각 / 4:3 웹캠 기본 / 3:4 세로 / 16:9 와이드 / 9:16 숏폼 / 3:2 사진 / 2:3 사진 세로
- **크기** — 아주 작게 ~ 최대 6단계. **현재 비율에 맞춰 실제 px 이 계산돼 표시된다** (16:9 · 보통 = `320 x 180`)
- **보정** — 피부 매끄럽게(약/보통/강하게), 피부톤(차갑게~따뜻하게), 밝기
- **인물 추적** — 켜기/끄기. **속도와 크기는 설정 패널의 슬라이더**에서 1~10 으로 조절한다
- **배경** — 끄기 / 투명(바탕화면 비침) / 흐리게 / 단색. 사람만 남기고 배경을 지운다
- **테두리** — 두께(없음~4px), 색상 프리셋 및 직접 선택
- **투명도** — 25 / 50 / 75 / 100 %
- **카메라** — 연결된 장치 목록에서 선택, 다시 연결
- **좌우 반전**, **항상 맨 위**, **클릭 통과**, **창 숨기기**, **종료**

## 설정 패널

슬라이더로 조절하는 것들은 창 **옆에 뜨는 패널**에 모여 있다. 메뉴가 아니라 별도 창인 이유는, 메뉴는 항목을 누르면 무조건 닫혀서 값을 보며 맞출 수 없고 팝업이 영상을 덮어 결과가 안 보이기 때문이다.

| 구역 | 내용 |
| --- | --- |
| **인물 추적** | 켜기/끄기 · **속도 1~10** · **크기 1~10** |
| **배경** | 끄기 / 투명 / 흐리게 / 단색 · 흐림 강도 1~50 · 배경 색 |
| **화면** | 투명도 20~100% · 테두리 두께 0~8px · 테두리 색 |
| **보정** | 피부 매끄럽게 0~100 · 피부톤 ±50 · 밝기 ±50 |

- 드래그하는 내내 **실시간으로 반영**된다. 설정 저장은 손을 뗀 뒤 600ms 에 한 번만 일어난다
- 뜰 때 **포커스를 뺏지 않는다** (`WA_ShowWithoutActivating`) — 방송 중에 써도 안전하다. 슬라이더를 클릭하는 순간에만 패널이 활성화된다
- 슬라이더는 홈 아무 데나 눌러도 그 지점으로 바로 가고 드래그가 이어진다
- `Esc` 로도 닫히지만, 포커스를 뺏지 않는 창이라 **패널 안을 한 번 클릭한 뒤에만** 키가 도달한다
- 의미 없는 컨트롤은 회색으로 바뀐다 (추적이 꺼져 있으면 속도·크기, 배경이 '흐리게'가 아니면 흐림 강도, 모양이 '없음'이면 테두리 등)
- 예전 메뉴에도 같은 항목이 남아 있다. 메뉴 정리는 다음 단계다

## 주의: 클릭 통과

켜면 마우스 이벤트가 창을 그대로 통과해 뒤쪽 창으로 전달된다.
**창을 마우스로 잡을 수 없게 되므로**, 끄려면 `Ctrl+Alt+C` 또는 트레이 아이콘 메뉴를 사용한다.

## 설정 저장

위치·크기·모양·카메라 등 모든 설정은 아래에 저장되고 재실행 시 복원된다.

```
%APPDATA%\WebcamMirror\settings.json
```

저장된 좌표가 현재 모니터 구성에서 보이지 않으면(모니터를 분리한 경우 등) 주 모니터 우하단으로 자동 복귀한다.
파일이 손상됐으면 기본값으로 시작하므로, 설정을 되돌리고 싶으면 이 파일을 지우면 된다.

## exe 빌드

```bash
build.bat
```

`dist\WebcamMirror.exe` 가 생성된다. 설정은 `%APPDATA%` 에 저장되므로 exe 를 아무 데나 옮겨도 된다.

## 알려진 사항

- 가상 카메라(OBS, PRISM, Imaging Edge 등)도 목록에 함께 나타난다. 원본 기기가 송출 중이 아니면 검은 화면이 보일 수 있으니, 우클릭 → 카메라에서 실제 웹캠을 고르면 된다.
- 영상은 **cover** 방식으로 그려진다. 창 비율에 맞춰 원본을 중앙 기준으로 잘라내므로 어떤 비율에서도 얼굴이 찌그러지지 않는다.
- 보정과 배경 처리는 캡처 스레드에서 1280x720 을 640 폭으로 줄인 뒤 처리한다. 창은 보통 이보다 작아 화질 손실은 보이지 않는다. 실측 프레임당 비용:

  | 설정 | 비용 |
  | --- | --- |
  | 보정만 | 9.8 ms |
  | 배경 투명 | 10.8 ms |
  | 배경 흐리게 | 16.7 ms |
  | 배경 단색 | 14.5 ms |
  | 보정 + 배경 흐리게 | 26.1 ms |

  30fps 예산이 33ms 이므로 전부 켜도 여유가 있다.
- 피부 인식은 YCrCb 색 범위 기반이라 조명이 심하게 치우치면 배경의 나무색·살구색 벽이 함께 보정될 수 있다. 그럴 땐 강도를 낮추면 된다.
- 배경 제거는 256x256 입력이라 머리카락 같은 가는 경계는 뭉개진다. 작은 오버레이 창에서는 눈에 잘 띄지 않는다.
- 추론 주기는 **처리 시간을 재서 스스로 조절한다**. 여유가 있으면 매 프레임 추론해 움직임을 정확히 따라가고, 30ms 를 넘기면 2~3 프레임에 한 번으로 내려가 직전 마스크를 재사용한다 (22ms 아래로 내려오면 복귀). 판단은 **프레임 전체** 시간으로 하되, 세그멘테이션이 비용의 의미 있는 몫일 때만 물러선다 — 피부 보정 때문에 느린 건데 추론을 건너뛰어봐야 소용없기 때문이다.
- 마스크 경계는 **Fast Guided Filter**(He & Sun)로 원본 윤곽에 맞춘다. 계수 `a, b` 를 4배 축소 격자에서 구한 뒤 **계수를 업샘플해 `q = a·I + b` 를 풀해상도에서 적용**하는 것이 핵심이다. 이 정제는 반드시 대비 커브 **앞에** 와야 한다 — 커브는 소프트 알파 밴드를 없애는데 그 밴드가 바로 머리카락이다. 타이트한 클로즈업에서 윤곽 일치도 0.917 → 0.966, 소프트 밴드 0.0098 → 0.0213 (머리카락 보존).
- **추적 속도·크기는 1~10 이지만 내부 매핑은 비선형이다.** 눈금을 선형으로 두면 한쪽 절반이 전부 비슷하게 느껴진다. 속도는 시정수를 로그 보간하고(한 칸에 약 35%, `속도 6` = 예전 기본값 τ≈0.27초), 크기는 역수를 선형 보간해 화면상 인물 크기가 등간격으로 변하게 한다. 데드존도 속도에서 파생된다 — 기본값에서 예전의 2.1배(0.030 → 0.063)라 미세한 떨림이 사라진다.
- **이징은 경과 시간 기반이다.** 예전에는 프레임당 고정 비율(`0.12`)이라 30fps 웹캠과 60fps 웹캠에서 따라오는 속도가 정확히 2배 달랐다 — 속도 슬라이더의 눈금이 카메라마다 다른 뜻이 되므로 먼저 고쳤다.
- **속도·크기 슬라이더는 `processor.reset()` 을 부르지 않는다.** 부르면 드래그하는 내내 프레이밍이 원위치로 튄다. `reset_track()` 은 추적을 켜고 끌 때만 부른다.
- **아이콘 `.ico` 는 직접 조립한다.** Qt 는 ICO 를 읽기만 하고 쓰지 못해서 `pixmap.save(..., "ICO")` 가 256px 한 장짜리 파일을 만들었고, Windows 가 그걸 16px 로 다운샘플해 작업표시줄에서 뭉갰다. 지금은 8개 프레임(16~256)을 PNG 페이로드로 담는다 — 270KB → 15KB.
- **인물 추적**은 배경 제거와 **같은 마스크를 나눠 쓴다** — 추가 추론이 없다. 마스크의 바운딩 박스를 창 비율에 맞춰 넓힌 뒤 그 영역만 잘라낸다. 마스크가 미세하게 떨려도 화면이 흔들리지 않도록 (1) 목표가 데드존(프레임의 3%)을 벗어날 때만 갱신하고 (2) 현재 프레이밍을 목표 쪽으로 이징한다. 크기는 위치의 절반 속도로 따라가 줌이 들썩이지 않는다. 실측: 정지 시 프레임간 흔들림 **0.00px**, 인물이 203px 이동할 때 프레임당 2.29px 로 추종.
- 시간축 평활은 **움직임 적응**이다. 안 움직인 픽셀은 직전 마스크를 최대 0.75 가중치로 섞어 깜빡임을 죽이고, 움직인 픽셀은 새 값을 그대로 써서 잔상을 막는다.
- 채택하지 않은 것들: 중앙 정사각 크롭 추론(구도에 따라 엇갈림), 인물 추적 ROI 크롭(오히려 나빠짐 — 이 모델은 웹캠 전체 화면을 전제로 학습됨), MediaPipe 멀티클래스 모델(OpenCV 가 `TRANSPOSE_CONV` 를 못 읽고, LiteRT 로 돌리면 추론이 240ms 라 실시간 불가), 대체 모델 전반(상업 배포 가능 + `cv2.dnn` 로드 가능 + 20ms 이내 + 머리카락 개선을 동시에 만족하는 것이 없음).
- **16:9 를 1:1 로 찌그러뜨려 모델에 넣는 것은 의도된 동작이다.** MediaPipe 의 `selfie_segmentation_cpu.pbtxt` 가 `keep_aspect_ratio: false` 다. 레터박스로 바꾸지 말 것.
- 추론은 **onnxruntime CPU** 로 돌린다. 같은 모델을 `cv2.dnn` 으로 돌리면 23.1ms, onnxruntime 으로는 **4.4ms** 다 (5.2배). 두 백엔드의 출력은 최대 오차 0.000036, 0.5 기준 일치율 100% 로 사실상 동일함을 확인하고 채택했다. onnxruntime 이 없거나 `.onnx` 가 빠지면 자동으로 `cv2.dnn` + TFLite 로 떨어진다 — 우클릭 메뉴 맨 아래에 지금 어느 백엔드를 쓰는지 표시된다.
- 모델을 ONNX 로 직접 변환하려 했으나 **Python 3.14 에는 TensorFlow 휠이 없어** `tf2onnx` 를 쓸 수 없고, TF 없이 도는 `tflite2onnx` 는 이 모델의 `HARD_SWISH` 를 지원하지 않는다. 그래서 `onnx-community` 의 변환본을 받아 **수치 일치를 검증한 뒤** 채택했다.
- PyInstaller 로 묶을 때 `--collect-binaries onnxruntime` 과 `--noupx` 가 필요하다. ORT 의 provider DLL 이 UPX 로 압축되면 로드에 실패하는 것이 알려진 문제다.
- OpenCV pip 휠에는 **GPU 지원이 없다.** `DNN_BACKEND_CUDA` 상수는 존재하고 `setPreferableTarget` 도 예외를 안 던지지만 전부 CPU 로 떨어진다. 확인법은 `'CUDA' in cv2.getBuildInformation()` 뿐. `readNetFromTFLite` 의 두 번째 인자로 `ENGINE_CLASSIC` 을 주면 기본 엔진보다 빠르다 (19.0ms vs 21.5ms).
- 처음에는 OpenCV Zoo 의 PPHumanSeg 를 썼으나, 상반신 인물 사진으로 학습된 모델이라 얼굴이 화면을 채우는 클로즈업에서 마스크가 얼굴을 파먹었다. 웹캠 셀피가 주 용도인 MediaPipe 모델로 바꾸니 같은 조건에서 애매한 경계 비율이 0.313 → 0.019 로 떨어졌고, 용량도 5.9MB → 244KB 로 줄었다.
- **투명 배경**을 쓸 땐 모양을 `없음 (전체)` 으로 두는 편이 자연스럽다. 원형으로 잘려 있으면 인물이 원 밖으로 나갈 때 잘린다.
- `assets/selfie_seg.tflite` 가 없으면 배경 메뉴만 비활성으로 표시되고 나머지 기능은 정상 동작한다.
- 모델은 경로가 아니라 **바이트로 읽어** `cv2.dnn` 에 넘긴다. OpenCV 의 파일 입출력은 Windows 에서 경로에 비ASCII 문자가 있으면 실패하는데, exe 로 묶으면 모델이 `%TEMP%\_MEIxxxx` 로 풀려 사용자 이름이 한글이면 그 경로가 비ASCII 가 된다. 개발 중에는 드러나지 않고 exe 에서만 배경 제거가 조용히 죽는 문제였다.
